# ADR-001：部署形态决策——官方固件 + SDK 部署，不自制运控全栈刷机

> 状态：**已决策**（2026-10-21）。提出背景：deploy/README.md §1 三条链路的取舍讨论。
> 约束：AGENTS.md——当前授权只做调研与预案，不连真机、不执行安装/服务/固件脚本。

## 决策

K1 的 RL 策略部署**基于官方固件 + booster_sdk / booster_deploy**（策略作为普通进程，经 DDS 低层接口读写机器人），**不采用** B-Human 式的整套自有运控栈刷机（`Install/installRobot` + Deploy Dialog）。

## 两种形态对比

| | 官方固件 + SDK（选定） | B-Human 全栈刷机（不选） |
|---|---|---|
| 机器人运行环境 | 原厂固件不变，策略进程经 `/low_state`、`/joint_ctrl` 等 DDS 话题交互 | installRobot 把 B-Human 软件装成机器人运行系统（NAO 时代为刷自有 OS 镜像，K1/T1 延续同思路），Deploy Dialog 日常下发 |
| 运控与安全责任 | 官方固件兜底（电机驱动、高频 PD、底层保护）；策略只管 50 Hz 关节位置目标 | 全部自负：运控、感知、行为、推理都在自有栈内 |
| 推理形态 | JIT `.pt`（booster_gym 范式）或 ONNX（RoboNaldo_Deploy 范式） | C++ 栈内 CompiledNN（x86）/ ONNX Runtime（ARM，K1 实际走这条） |
| 社区先例 | NOMADZ nomadz_deploy（K1 上 MimicKit AMP 转向/带球）、NaoHTWK htwk-gym、官方 robocup_demo | B-Human 自家比赛栈 |
| 工程量与风险 | 低 | 高，且需自建安全体系 |

## 理由

1. 本课题目标（在公开步态基础上训更强步态 + 反应技能）的全部迭代工作都不需要替换机器人运行系统；
2. booster_deploy 已实现「同一份策略代码跑 MuJoCo/Webots/真机」，与仓库 sim2sim 门（inventory/06）天然衔接；
3. 官方固件保留原厂安全保护，符合「保护机器人、先仿真后真机」的上机纪律；
4. 自制全栈刷机直接违反 AGENTS.md 当前授权范围，且与「保留官方 B-Human 步态与官方比赛感知」的保护条款方向相反。

## 例外与边界

1. **B-Human 比赛栈例外**：BHumanCodeRelease 本身是刷机级全栈。若未来要用其整套比赛行为参赛，installRobot 步骤不可绕过——届时单独评审（含固件版本矩阵 deploy/README.md §3、同机环境切换方案），且必须在获得明确授权后执行。
2. **SDK 边界**：SDK 提供接口与示例，不提供球感知/定位/团队策略——这些由路线 B 反应技能（research/survey/B）补齐。
3. 本决策可随时因授权范围变化而修订；修订即更新本 ADR 并留痕。
