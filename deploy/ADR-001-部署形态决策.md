# ADR-001：部署形态决策——官方固件 + SDK 部署，不动 B-Human 式装机

> 状态：**已决策**（2026-10-21；2026-10-21 修订表述，见文末修订记录）。提出背景：deploy/README.md §1 三条链路的取舍讨论。
> 约束：AGENTS.md——当前授权只做调研与预案，不连真机、不执行安装/服务/固件脚本。

## 决策

K1 的 RL 策略部署**基于官方固件 + booster_sdk / booster_deploy**（策略作为普通进程，经 DDS 低层接口读写机器人），**不采用** B-Human 式装机（`Install/installRobot` 打补丁 + Deploy Dialog/deploy 脚本下发自有栈）。

## 两种形态对比

| | 官方固件 + SDK（选定） | B-Human 栈（不选；机制详见 deploy/bhuman-部署机制.md） |
|---|---|---|
| 机器人运行环境 | 原厂固件不变，策略进程经 `/low_state`、`/joint_ctrl` 等 DDS 话题交互 | installRobot 在**官方镜像上打补丁**（systemd 用户服务 bhuman.service + 按键/手柄路由 + 网络配置；整镜像刷机是 NAO 时代做法，K1/T1 2026 版已不刷镜像），之后 deploy 脚本/Deploy Dialog 下发 Config + bhuman 可执行文件 |
| 运控与安全责任 | 官方固件兜底（电机驱动、高频 PD、底层保护）；策略只管 50 Hz 关节位置目标 | 全部在 B-Human 单进程栈内（运控、感知、行为、推理） |
| 推理形态 | JIT `.pt`（booster_gym 范式）或 ONNX（RoboNaldo_Deploy 范式） | 栈内推理：ARM/Jetson 上 ONNX Runtime + TensorRT 缓存（Config/NeuralNets/TensorRTCache） |
| 社区先例 | NOMADZ nomadz_deploy（K1 上 MimicKit AMP 转向/带球）、NaoHTWK htwk-gym、官方 robocup_demo | B-Human 自家比赛栈 |
| 工程量与风险 | 低 | 高，且需自建安全体系 |

## 理由

1. 本课题目标（在公开步态基础上训更强步态 + 反应技能）的全部迭代工作都不需要改动机器人运行系统；
2. booster_deploy 已实现「同一份策略代码跑 MuJoCo/Webots/真机」，与仓库 sim2sim 门（inventory/06）天然衔接；
3. 官方固件保留原厂安全保护，符合「保护机器人、先仿真后真机」的上机纪律；
4. B-Human 式装机属于 AGENTS.md 明令禁止的「机器人安装/服务脚本」，且与「保留官方 B-Human 步态与官方比赛感知」的保护条款方向相反。

## 例外与边界

1. **B-Human 比赛栈例外**：若未来要用 BHumanCodeRelease 整套比赛行为参赛，installRobot + deploy 链路不可绕过——届时单独评审（固件版本矩阵 deploy/README.md §3、TensorRT 缓存绑定硬件导致的 ≥10 分钟首启动、同机环境切换方案），且必须在获得明确授权后执行。
2. **SDK 边界**：SDK 提供接口与示例，不提供球感知/定位/团队策略——这些由路线 B 反应技能（research/survey/B）补齐。
3. 本决策可随时因授权范围变化而修订；修订即更新本 ADR 并留痕。
