# 盘点 01 · 归档与恢复体系（archive/ + archive-tools/）

> 盘点日期 2026-10-21；信息来自 main 分支文件实读。本系列笔记每模块一份、单独提交，作为全量盘点的留痕。

## 是什么

仓库的「证据与灾备层」：13.34GB 公开工作树 + 3.70GB 加密原始 Git 历史，全部以分卷形式存于 GitHub Releases，逐文件 SHA256 可验。

## 结构

| 路径 | 内容 |
|---|---|
| `archive-tools/restore.py` | **主入口**：下载→逐分卷 SHA256 校验→解压→逐文件复核；拒绝覆盖未知/已改文件；支持 `--training-only`（78MB 训练包）、`--download-cache`（断点续传）、`--with-original-history`（gpg 解密原始历史） |
| `archive-tools/package.py` / `package_runtime.py` | 打包容器（快照包 / 20261020 运行包） |
| `archive-tools/training_kit.py` | 生成 k1-training-kit 清单 |
| `archive-tools/verify_archive.py` / `verify_remote.py` | 本地/远端校验 |
| `archive-tools/inventory.py` / `scan_git_history.py` | 清点与 Git 历史扫描 |
| `archive-tools/upload_*.py` | 64MiB 分块上传，逐块重试 |
| `archive/assets-manifest.json` | Release 分卷清单（tag、大小、SHA256） |
| `archive/public-files.jsonl` (12MB) | 公开工作树 41272 个文件的逐文件哈希 |
| `archive/encrypted-original-files.jsonl` | 加密归档 9589 文件哈希 |
| `archive/git-origins.json` | **15 个嵌套上游仓库的 HEAD/remote/本地修改清单**（见下） |
| `archive/retention-and-publication-policy.json` | 本地保留清单、清理前置条件、上传纪律 |
| `archive/remote-verification.json` 等 | 各轮验收证据 |

## 怎么用最好

1. **任何新机器起步**：`restore.py --training-only` 拿 78MB 训练包 → 验环境 → 再决定要不要 13GB 全量。
2. **依赖不进归档**：Python 环境、Gym 安装包、ONNX Runtime 依赖只在本机保留（policy 里 local_retention 清单）；恢复脚本不装依赖。
3. **恢复密钥**在本机 `~/.local/share/robocup-archive/recovery-key.txt`（0600，从未上传）；没有它也能恢复全部公开成果，只是解不开原始历史。
4. **restore.py 可直接复用为「产物发布模板」**：将来发布自训练策略包时，照它的 清单+SHA256+拒绝覆盖 模式做（README 第六节也这么建议）。

## 与其他模块的连接

- 训练主线（k1-training）的全部检查点语义、环境锁都在 `manifests/`，归档只存指针；
- 比赛验证（local-k1-validation）的运行时 `runtime/` 被明确排除在归档外；
- research 分支（本系列笔记）独立于归档体系，纯链接与笔记。

## 风险/注意

- `robocup/` 有 **16 个本地提交未推上游**（sandbox/thu/thu_master），原始历史只在加密归档里；这是全仓库唯一「不可从公网重建」的代码资产，恢复密钥丢失=这段历史不可读。
- SDK 锁在 **fw-1.6**，而 booster_deploy 新文档要 ≥1.7.2、B-Human 文档测 1.7.1——真机阶段必须先核版本。
