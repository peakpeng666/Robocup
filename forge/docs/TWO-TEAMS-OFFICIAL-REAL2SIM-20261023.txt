一、A 方究竟怎样把真机代码用于仿真

本地源码给出的实际路径：

Make/CMake/B-Human.cmake：同一组 Modules、Representations、Threads、Tools 组成 B-Human 对象库。
Make/CMake/Booster.cmake：机器人程序链接 B-Human + Booster SDK，按 ARM 目标构建。
Make/CMake/SimulatedRobot.cmake：仿真控制器同样链接 B-Human，在 PC 本机执行。

  B-Human 感知 -> 世界建模 -> 战术/技能 -> MotionRequest -> 自有完整 MotionEngine
       +-- 真机：BoosterProvider / CameraProvider / SDK DDS -> K1 传感器与电机
       +-- 仿真：LocalConsole / SimulatedRobot3D -> 渲染相机、关节/IMU与物理执行器

BoosterProvider 读取 LowState、使用 Custom 模式并发布自身算出的 LowCmd。
SimulatedRobot3D 读取模拟关节/IMU和相机，将同一运动代码的目标与电机参数交给 SimRobot。
这就是共享控制实现、切换 IO；不是把 RoboCupDemo 当成 B-Human 的上层。

二、B 方需要对应建立的路径

  官方比赛应用（vision / brain / 裁判与队间通信，沿用真机算法、模型和行为树）
       -> 原有 SDK/ROS 2 请求、反馈、时间与坐标契约
       -> 官方 1.6 运控（模式、状态估计、行走、起身、保护、踢传、头臂等）
       -> 仿真硬件 IO -> B 方 K1 物理模型

真机时继续使用原来的 SDK/DDS 和已安装的匹配 1.6 固件。
仿真时替换硬件、传感器、通信与时钟后端，尽量保持其余程序不变。
不能因为缺少原厂 PC 可重编译源码，就推断原来的真机应用不能部署。
当前原厂 ARM/QEMU 核心作为完整原厂行为的参照；执行速度很慢，需要独立解决。
任何另外实现的快速后端均需披露来源并逐项对照，不能因接口相同就叫原厂全部实现。

五、下一阶段的具体接入契约

1. 请求：LocoApiTopic[/robot_name]Req 的 api_id、JSON body、UUID 与真实原厂响应对应。
   原样保留 SDK 请求，不能重新借助 B-Human MotionRequest 来生成另一套动作。
   call() 的 publish 返回 0 不等于原厂接受，原厂接受也不等于动作完成。
2. 反馈：500 Hz LowState 的串联/并联关节与 IMU、原厂里程计、头部姿态、恢复与模式状态。
   明确哪一项来自物理传感器、原厂估计或标定；禁止把球/场地真值冒充正常感知。
3. 视觉：从候选自己的 SimRobot CameraColor 与 CameraDepth 提供正常 RGB/深度、CameraInfo 和外参，
   运行官方 vision；候选不得消费 A 方 BallModel、定位结果或策略输出。
   原有 K1 场景已包含 544x448 RGB 与深度传感器，不需要把场地真值当视觉输入。
4. 视觉踢球：除 VisualKick(start,version) 外，还需完整 /kick_ball 球、方向、球门、朝向、power 和时间戳。
5. 时间：所有原厂电机周期、相机/反馈时间戳、ROS /clock 与应用频率使用同一个仿真时间基准。
   官方 brain/main.cpp 当前在 tick 后用 std::this_thread::sleep_for(10 ms) 睡墙钟；
   只设置 use_sim_time 不能改变该睡眠。需要明确的时钟后端适配，并保留真机运行时的对应路径。
6. 裁判与通信：按各自原协议读取同一世界的比赛数据，为每台候选隔离话题/状态/历史与通信身份。
7. 完整性：模式、各 gait、启停/倒地/保护、起身、头臂、踢传和真实球接触逐项产生新证据。
8. 部署准备：保持官方 SDK 与 ARM/Jetson 构建路径，核对 .run、SDK、比赛代码、模型、ROS/DDS ABI 的版本组合。
   Demo 文档的 1.6.1/1.6.2 功能要求与本机 1.6.0.10 包之间的命名/功能映射仍需实测。

   Src/Modules/Infrastructure/LogDataProvider/LogDataProvider.cpp:91 把消息读进相同的 Representation。

3. 同一运动输出的两个去向
   真机 Src/Modules/Infrastructure/BoosterProvider/BoosterProvider.cpp:144 读取 LowState，
   :374 将 JointRequest/MotorParameters 转为 LowCmd，:420 通过 DDS 发给硬件；
   相机由 X5CameraProvider 等硬件提供者负责。
   仿真 Includes/DebugResponses.con:7,9 请求 JointRequest/MotorParameters，
   Src/Libs/SimulatedRobot/RobotConsole.cpp:649,675 收取原算法输出，LocalConsole.cpp:239

4. 同一逻辑时间下的闭环
   NormalWithJPEG.con:4 开启 st on；Src/Libs/Platform/Time.cpp:47,59,67 切换和推进模拟时间；
   Src/Libs/SimulatedRobot/RoboCupCtrl.cpp:434 按物理步长推进。
   LocalConsole 按时间安排图像/关节输入，完整帧驱动对应线程。
   不能机械地把 B-Human 的每个线程频率搬给 B 方；要保留官方程序自身的控制周期和时序契约。
