# 在 SimRobot 中验证运控与足球战术

2026-10-22。目标是让一项改动可以选择、运行、对照和复查。两种实验都使用本机真实 SimRobot、
B-Human 正常渲染相机和现有 K1 资产。每次实验创建新的 arena，不改变 `main` 或 `codelab` 的队伍选择。

## 从界面开始

在桌面会话中运行 `bash /home/peakpeng/Desktop/Robocup/forge/bin/forge-server`，打开终端给出的本机地址。
进入 **SimRobot 验证**；窄窗口用上方“切换页面”选择。服务已运行时直接使用现有页面。

1. **运控验证**：选择候选运控包。普通 ONNX 包选程序来源 `main`；`forge-walk-filter-a03` 选包含该模块的 `codelab`。
2. **策略验证**：双方选择同一个运控包，再选择候选足球行为策略。右侧可从“提前搜球”或“延长接应等待”建立新的参数配置。
3. 点“查看计划”检查场景数，再点“开始验证”。作业页显示进程状态和实时日志，支持取消。
4. 返回验证页，选择记录和具体场景，查看对照指标、轨迹回放、录像、实际参数回读、启动清单和原始日志。

“运行完成”只表示流程执行完毕。性能结论单独展示，运行失败或缺少加载证据时不会判为通过。

## 运控验证

`motion-basic-v1` 在原本的单机器人 K1 场景中运行，每次 30 秒。通过 SimRobot 控制台设置完整 `MotionRequest`：

| 仿真时间 | 请求 | 观测 |
|---|---|---|
| 0–2 秒 | 站立 | 初始化与参数回读 |
| 2–10 秒 | 前进，relative x=0.35 | 身体坐标系累计前进距离 |
| 10–16 秒 | 左移，relative y=0.3 | 身体坐标系累计侧移距离 |
| 16–24 秒 | 转向，relative rotation=0.25 | 解包角度后的累计偏航 |
| 24–30 秒 | 站立 | 26–30 秒净漂移 |

这些是**相对速度请求**，不能解读成 0.35 m/s、0.3 m/s 或 0.25 rad/s。
官方和候选各跑一次；第二次重复反转执行顺序。两者都保持官方行为配置。
来源程序对双方一致，新增代码模块通过运控包显式选择；修改了既有官方代码的变体不能冒充保留官方对照。

每场检查进程正常退出、完整仿真步数、正常相机观测、实际网络加载、完整指令下发、参数回读、跌倒/起身和录像完整性。
基本响应需前进超过 1 米、侧移超过 0.3 米、转角超过 0.3 rad、停止漂移小于 0.1 米。
对照规则在计划中保存：候选的前进、侧移和转角响应均至少达到官方均值的 80%，停止漂移不超过 0.1 米。

这是一组发现明显退化的固定指令实验，尚未覆盖精确目标速度 RMSE、反向指令、侧向串扰、能耗、足滑、恢复或随机推扰。
响应更大也不自动表示控制更好。正式晋级仍使用独立多引擎门控，不能拿此处的“未观察到退化”替代晋级。

## 足球战术验证

策略配置与运控包分别保存，组合时记录两个原始身份。当前支持官方行为层的搜球、丢球、接应等时间参数，
参数有名称、类型、范围校验；不允许通过这个入口改变视觉、步态或任意模块。
配置按内容寻址，已有配置不被覆盖。策略页面创建的是新的实验候选，不表示它优于官方。

每次重复包含四场 3v3，默认每场 120 秒，可选 60–600 秒：

| 候选所在队伍 | 初始开球队伍 |
|---|---|
| T5 | T5 |
| T70 | T5 |
| T70 | T70 |
| T5 | T70 |

两队使用同一个运控包，基线使用官方行为配置。队伍和初始开球都互换，减少仅由选边、队号或开球带来的偏差。
比赛使用 SimRobot 内置裁判。进球后的重开球仍按裁判规则执行；这里没有接入外部 GameController。

每台机器人在运行中通过 Cognition 请求保存三个实际配置：

- `representation:BehaviorParameters`
- `module:SkillBehaviorControl`
- `module:StrategyBehaviorControl`

系统逐个标量比较实际值和预期配置，记录输出文件哈希。检查的是实际进程回读，不只是磁盘上有没有写入文件。
结果按**候选/官方**身份汇总胜平负、进失球、触球样本、跌倒事件、可见球样本与各类技能请求，随队号互换正确归组。

机器人轨迹与行为请求约每 0.5 秒采样，触球日志有约 0.1 秒限频。
因此技能请求计数不是成功传球/射门次数，触球样本不是完整控球率，采样跌倒也不是逐帧完整事件标注。
四场短赛只产出待审阅证据，不自动认定战术更强；候选采样跌倒多于基线会提示退化。

目前接入的是**行为参数候选**。全新 C++ 战术模块或端到端足球战术网络仍需要明确输入输出契约、模块适配和动作结果审计；
现有 344→13 步态 ONNX 只负责运控，不能作为通用足球战术网络直接导入。
官方行为层的分工可参考 [B-Human 行为文档](https://docs.b-human.de/coderelease2026/behavior/overview/)，
控制台与场景机制见 [SimRobot 文档](https://docs.b-human.de/coderelease2026/simrobot/)。

## CLI

```bash
F=/home/peakpeng/Desktop/Robocup/forge/bin/forge

# 只看计划，不启动仿真
$F validate motion --motion-pack thu-amp-s42-it400-5650b21712 --preview

# 官方对官方：先确认场景自身可以重复运行
$F validate motion --motion-pack bhuman-official

# 独立 C++ 运控模块：需要该模块对应的已编译程序
$F validate motion --motion-pack forge-walk-filter-a03-01d82b81e8 --arena codelab

# 新的足球行为配置；命令输出其内容寻址 ID
$F strategy create --preset earlier-ball-search
$F strategy list
$F validate strategy --motion-pack bhuman-official \
  --strategy earlier-ball-search-d1458c3692 --seconds 120 --repetitions 1
```

`--repetitions` 支持 1–5；`--vision cpu` 使用 CPU 推理但仍渲染正常相机；`--no-record` 关闭录像采集。
两种模式都使用本机仿真锁，和既有比赛、配置选择操作互斥。

## 证据与中断

- `runs/validations/<时间戳>_<模式>/validation.json`：预先确定的计划、规则、候选快照、各场结果及其哈希、汇总结论。
- `arena/validation-<时间戳>-<模式>/`：每次验证独立的配置工作区。
- `runs/motion/` 或 `runs/matches/`：启动清单、二进制/控制器/场景/日程哈希、原始日志、执行信息、轨迹和结果。
- 每场的 `runtime-config/`：每台机器人的实际行为配置回读。
- 每场的 `frames/`、`frames-manifest.json`、`match.mp4`：原始 JPEG、逐帧哈希和观看副本。
- `runs/flash-history/`、`runs/arena-archives/`：重新选择配置和显式刷新 arena 时保留的历史。

阶段完成后即保存报告。正常取消/SIGTERM 写入 `INTERRUPTED` 并清理所属仿真进程；静默进程也受墙钟超时限制。
断电或 SIGKILL 不能执行清理，可能留下 `RUNNING` 报告；此类记录始终保留“证据不足”，仍需人工核查进程。
初始场景、请求和配置可复用，但多线程感知/策略不保证逐位确定；重复性结论要来自多次运行。

## 已完成的真实验证

| 实验 | 证据 | 结果 |
|---|---|---|
| 官方 vs AMP 400 轮运控 | `runs/validations/20261022_221141_807427_motion/validation.json` | 两场基本运行均通过；前进 5.198→3.435 米，响应约为官方的 66.1%，判为观察到退化 |
| 官方策略 vs 提前搜球 | `runs/validations/20261022_221349_143582_strategy/validation.json` | 四场各 120 秒，1 胜 1 平 2 负、进球 3:5，待审阅；72 份运行时配置回读通过 |
| 界面启动的官方 vs 官方 | `runs/validations/20261022_222831_694593_motion/validation.json` | 前进 5.185/5.204 米；四项对照检查均未观察到退化；队列作业退出码 0 |
| 界面启动的官方 vs C++ 滤波模块 | `runs/validations/20261022_223208_312635_motion/validation.json` | 前进 5.182/5.252 米、转角 4.018/3.925 rad；四项对照均未观察到退化，候选日志确认 `ForgeWalkingEngine alpha=0.3000` |

策略实验实际回读：候选的搜球阈值为 1500/5000 ms，官方为 2000/8000 ms，随队伍互换正确切换。
四场保留 4800 张原始 JPEG 帧。另三组运控对照各保留 600 张原始帧，共 6600 帧。
首个参数回读冒烟失败保留在 `runs/motion/20261022_220713_585960_motion-baseline-readback/`；
失败原因是模块请求命名空间错误，改用 `module:` 后以上新运行均通过，没有改写失败记录。
