# 附录 C：已执行验证与复现边界

## C1. 官方 K1 策略 CPU MuJoCo 回放

模型来自固定 B-Human MachineLearning commit。训练与比赛仓库的 K1_walk.onnx Git blob SHA 完全相同；下载后的文件 SHA256 为 9d1ec18504cb9d05ec708b9430783a2331cabf5415fc0db81c6318472e948e8f，558,557 字节。28 个所需资产共 12,446,526 字节，均有固定下载 URL、大小和 SHA256；源码包不重复收录模型/网格，可用清单脚本下载。

| 项目 | 本次实测 |
|---|---|
| 环境 | x86_64、Python 3.12.14、MuJoCo 3.3.7、ONNX Runtime 1.22.1、NumPy 2.2.6 |
| 时长 / 频率 | 16 秒物理时间；500 Hz 物理；50 Hz 策略，800 次推理 |
| 命令序列 | 0–2 s 站立；2–7 s 前进 0.5 m/s；7–10 s 横移 0.2 m/s；10–13 s 转向 0.4 rad/s；13–16 s 停止 |
| 跌倒/数值检查 | 未触发高度 <0.25 m 或倾角 >1.2 rad 的中止条件；无数值警告 |
| 姿态记录 | 10 Hz 采样最低高度 0.514943 m，最大倾角 0.059600 rad；非全物理步极值 |
| 时间测量 | CPU 墙钟 1.523 s；推理中位 0.059835 ms，p99 0.503421 ms |
| 视频 | 960×640，10 fps，H.264，16.000 s；同一次轨迹渲染，没有另拼成功轨迹 |

CPU 推理耗时不是 K1 机载端到端感知/运动时延。16 秒无跌倒只是短时集成测试，不涉及训练升级、草皮变化、球/对手、视觉、踢球、起身、裁判或团队比赛。

回放改编自上游独立脚本，不是正式 B-Human 进程。差异包括训练 YAML 的 PD 参数、关节速度差分/低通、历史初始化、站停相位和上肢过渡；正式部署的掉包处理和惯性估计也不同。下一阶段必须做生产预处理与控制合同对照，不能把同一权重误作两条执行链完全相同。

复现入口：`experiments/bhuman_cpu_baseline/README.md`。原始结果 `smoke_result.json`，10 Hz 测量 `smoke_trace.csv`，原始轨迹 `smoke_trajectory.npy`，渲染脚本 `render_smoke.py`。视频明确标注“官方预训练基线、没有新训练、没有硬件认证”。

## C2. 六个 IP 的协议闭环

在本机 127/8 回环网络实际创建六个 UDP socket，分别绑定 127.0.0.11/.12/.13 和 127.0.0.21/.22/.23。合成测试裁判端位于 127.0.0.10，发送 158 字节控制数据，收到六个不同源 IP 的 32 字节状态回报；队号/球衣号组合全部匹配。

该测试已运行并通过。它是独立 IP 的协议行为验证，不是 Linux 六个 namespace、真实 AP/交换机、真实 GC GUI、DDS、物理碰撞或六台自主机器人比赛的验证。原始执行结果保存为 `docs/udp-loopback-results.json`，脚本为 `tools/udp_loopback_smoke.py`。

## C3. 29 项协议与更新包测试

综合命令 `python3 -B -m unittest discover -s tests -v` 返回 exit 0；29 项通过，测试执行约 4.840 s、完整命令墙钟约 5.115 s。记录包含命令、Python 版本、stdout/stderr 与当时全部 Python 源文件 SHA256。

协议测试用真正的 C 编译器编译固定官方 RoboCupGameControlData.h，生成黄金字节，再比较 Python 解码、回报打包、字段单位与结构长度。还覆盖真值通道拒绝、错版本/长度、停止/处罚/陈旧包、READY/SET/timeout 区别、序列回绕/重复/乱序、浮点溢出、队伍报文预算。

更新包测试通过真实子进程构建和执行，覆盖两版本安装/升级/回退、相同安装幂等、同版本冲突、不可变版本、坏摘要/内容/大小、重复 ZIP 项、路径穿越、符号链接、已有目录保护、并发安装锁，以及提交 current 链接 I/O 故障后的指针恢复。还验证摘要自洽但声称 robot_firmware 的包被明确拒绝。

结果见 `docs/validation-results.json`；安装器子任务的 20 项独立测试及源码哈希另见 `release/test-results.json`。最终 `.run` 内容在交付前另做包完整性与实际安装检查，执行结果在完整源码 ZIP 的 `release/final-package-checks.json`。
