优先只读研究和做差异清单，这一轮无需把三个官方新项目都安装成本机运行依赖。

技术选型：
- 前端可用 TypeScript/React/Vite；如果依赖下载或维护成本不合适，少依赖的 HTML/CSS/JS 也可以。选择一种完成可用软件，不为框架重建仿真。
- 后端采用轻量 Python API，优先让 Web 层不 import torch/isaacgym/isaacsim/mujoco。可用隔离的小 venv 或标准库方案，不向 bh-gym 里装 Web 依赖。
- 任务持久化可用 SQLite；记录运行身份和状态，别引入分布式调度集群。
- API 默认仅绑定 127.0.0.1；任务启动校验本地请求来源/会话，防止浏览器外站触发命令。提供列举后的任务类型和参数，不提供任意 shell 执行接口。
- 使用 subprocess 参数数组、明确 cwd、最小化进程环境增量；不要 shell=True 拼接用户输入。
- 不在 Web 后端运行 500Hz 控制循环，不通过浏览器逐关节发实时命令，不把所有 Python 环境合并。
- 系统启动仅加载元数据和证据，不自动运行训练、仿真、GPU 算子或机器人接口。

七、界面必须解决的实际工作

1. 项目总览与可点击依赖图
显示项目源码 → 配置/模型 → 解释器/环境 → 构建程序 → 仿真/训练 → 验证结果 → 离线产物的有向关系。
节点可展开真实绝对路径、版本、文件哈希/源码指纹、上游 SHA、依赖者、最后验收时间、验证范围和日志。
默认显示三条主链；Isaac Lab、Isaac Sim、Booster 官方新路线和其他已有 RoboCup/ROS 工具作为独立能力节点，按需展开。
依赖图必须来自机器可读发现结果，不是写死几张绿色卡片。
按需对关键资产哈希并缓存；不要每隔一秒扫描几 GB 文件。发现和启动前校验分开。

2. 环境和编译
区分目录存在、Python 包安装、解释器可执行、动态库就绪、历史运行通过、当前指纹下运行通过。
显示桌面 Release/Develop、ARM 构建、SDK/sysroot、实际推理后端、硬件利用率和当前任务。
GPU 查询是轻量状态，不自动升级为 GPU 压力测试。
缺失项给出具体失败项和替代方案，不把整个系统标成不可用。

3. 三条主要工作流
- 比赛：默认官方 gait + 正常相机，有限时间、录像、查看真实运动/感知/行为指标。
- sim2sim：官方策略默认，显式候选选择，CPU/可选窗口，查看轨迹、关节、力矩、超调和策略数值比较。
- 训练：明确 warm-start/full/actor-only 回放语义、任务、种子、环境数、迭代和预算；显示 actor/critic 是否更新、父检查点、有效配置和拒绝更新统计。
用户执行前可看解析后的命令、输入和预算；不能通过界面把默认官方模型切成“最新文件”。

4. 模型注册与比较
四种策略分别建契约，禁止仅按 .onnx/.pth 扩展名判断通用兼容：

行走 actor 为 344→256→128→128→13，ELU；13 输出是 12 腿动作与步态频率，不是 13 个电机。

显示 source checkpoint、导出器版本、opset、输入名称/形状/dtype、输出解码、归一化、历史布局、单位、关节顺序、动作幅值/限位、配置 profile 和验证证据。
当前 reference 候选标为实验候选；没有质量通过记录不得标为比赛可部署。

5. 作业与日志
状态至少区分 queued/running/succeeded/failed/cancelled/timed_out/interrupted。
另外单独记录质量 verdict：PASS/FAIL/INSUFFICIENT/NOT_EVALUATED，不能让 succeeded 自动等于策略质量 PASS。
持久化 job_id、argv、cwd、开始/结束时间、退出码、资源锁、环境身份、源码和模型哈希、有效配置、父子检查点、产物位置。
现有 managed_run 产生的 launch/execution/result/metrics 是事实来源；工作台建立索引和适配，不另写一份与底层矛盾的 PASS。
通过 SSE/WebSocket 或合理轮询显示增量日志/进度，日志滚动有界；控制线程不阻塞服务器。
任务由工作台创建的进程组管理，取消只停止自己的组，超时后回收子进程。禁止全局 pkill python/SimRobot。
重启后仍可看旧任务；不能只因 PID 存在就判为同一任务，更不能自动重启上一次正式训练。
GPU 训练与 GPU 视觉比赛默认互斥，构建任务也应有资源上限，避免性能验收互相污染。沿用已有 .bhuman-sim.lock，不绕过其互斥。

6. 回放和证据
直接查看已生成 MP4、结果 JSON、训练曲线、关节/力矩曲线、场地状态和测试失败项。
现有 ROOT/robocup/tools/telemetry_viewer 可复用部分界面和录像/回放逻辑，但其 UDP JSON 协议不是 B-Human 审计日志协议。必须做显式 adapter 与坐标/单位/时间校验。
viewer_server.py 的 UDP 默认绑定 0.0.0.0:15000，不能直接启动其默认联网接收器。优先离线文件回放，确需本机消息通道时仅本机绑定且与实机隔离。
区分比赛渲染相机、观赛视频、MuJoCo 观察者相机、机器人感知结果和仿真真值。真值可以用于诊断显示，不得暗中进入比赛策略感知链。
原始 B-Human 二进制 .log 优先调用已存在的 SimRobot 回放/转换工具，不能伪装为所有格式都已解析。

八、“仿真编译与真机等价”的工程定义和必须补的验证

用户希望尽量使用同一套代码，但不能把不同 CPU 架构编译成同一个二进制，也不能用未上机的仿真宣称物理等价。请实现并展示以下分层矩阵：

L0 资产身份：源码/模型/配置/依赖哈希明确，原版和实验 profile 可区分。
L1 网络数值：同一真实输入上，PyTorch/TorchScript/ORT/实际 C++ 推理后端输出在已声明误差内。
L2 输入输出契约：同一原始状态和历史下，生产 C++ 观测构造、历史更新、归一化、动作解码、限位与 Python 对照。
L3 调度与控制语义：策略门控、低层周期、PD/力矩模式、限幅、串并联映射和失效处理明确并离线验证。
L4 离线目标构建：实际 ARM64 ELF + 配套模型/配置/动态依赖和许可证可验证，目标 ABI/固件假设明确。
L5 真机闭环：需要后续单独授权与实物实验；本任务固定显示未验证，不因 L0-L4 通过自动打勾。

已有 MuJoCo 6000 输入的网络数值对照属于 L1 的一部分，不自动覆盖 L2-L5。
不同物理引擎的轨迹不要求逐位相同；必须先统一输入语义，再用行为和误差指标比较，不能把不一致轨迹直接当网络错误。

A. 最小生产 C++ 契约验收，先完成行走
必须让一项实际生产 C++ 行走编码/解码路径参与测试；不能只写一份“看起来一样”的新 C++ 或两份 Python 代码互证。
先检查能否通过已有 SimRobot 表示、离线回放、可选审计探针或链接现有代码构造测试入口。必要的小幅纯函数抽取/插桩放在独立实验适配中，并保留官方基线目录和启动入口。
不要为了让探针通过删掉官方哈希保护。若核心哈希因改动必须变化，实验构建与 baseline 分开，并记录行为不变的回归证据后再讨论接入。
用带唯一值和边界值的关节/IMU/命令序列，覆盖历史填充、10帧历史顺序、上一动作、相位、prepare、停止/转向、重置和时间门控。
先对齐同一输入快照/序列，再比较编码张量；报告每段索引 [start,end)、最大误差及首个不一致字段。
比较网络输出后的目标关节、频率解释、限幅和最终控制输出。为映射错误、mm/m、deg/rad、四元数 xyzw/wxyz、左右/轴方向各准备能失败的反例。
无法从现有生产路径导出某字段时，明确列为未覆盖并继续做可覆盖部分，不能换成自写同名函数后宣称生产契约通过。

B. 控制时序和关节语义
正常物理步/低层名义 2ms，策略名义 20ms，prepare 等分支以源码为准。
记录模拟时间、墙钟、策略调用数、控制更新数、观测时间戳、过期输入和 deadline 指标。加速运行不应改变模拟 dt。
已有某些力矩/关节指标只按 50Hz 末子步采样，不能把它们当 500Hz 全子步最坏值；标出采样率和已知盲区，有需要再加入有界降采样/极值汇总插桩。
目标限幅和测得关节超调分开；需求力矩、限幅后施加力矩、反馈估计分开，显示峰值与饱和占比的定义。
B-Human SERIAL 模式关节 q/dq 与 SDK 并联 Crank 电机状态不同，不能直接互换；实际串并联力矩转换/执行器特性仍有未验证项。
不要为求数值“统一”把训练 PD、B-Human regular、SimulatedK1 覆盖、fast low 档改成同一套值。
快速起身网络输出经解码并切换控制模式，不可直接把 22 输出标成 Nm。

ROOT/bhuman/local-k1-validation-20261019/bhuman-local/Make/CMake/Booster.cmake

D. 离线产物与 .run
先实现可验证的离线 bundle：实际 ARM 程序（如果成功构建）、配套官方模型/配置、manifest、依赖清单、许可证和校验工具。

不把整个开发 venv、NVIDIA Gym 安装包或密钥塞进 .run。

九、状态、证据和失效规则

能力状态建议：NOT_FOUND、PRESENT、INSTALLED、VERIFIED、STALE、UNVERIFIED、BLOCKED，并给出清楚含义；无需拘泥英文枚举名，但不能混为绿色“已就绪”。
保留每条证据的 created_at、source_fingerprint、config_hash、model_hash、runtime、scope、verdict、artifact_ref。
历史验证通过但当前模型/配置/代码变了，应显示历史通过且当前待重验，不悄悄沿用旧 PASS。
文件 mtime 不能独立证明身份；状态必须能追溯到日志/哈希。模型换了即使形状相同，也不能继承原策略质量通过。
对未来才有的能力显示具体缺项，不能用空图表和虚构数值占位。
环境导出清单只收集相关版本和白名单路径，环境变量/日志要避免泄露凭证。
前端下载/预览产物使用已登记 ID 和限定目录解析，拒绝目录穿越及 symlink 指向敏感路径。

十、实施顺序，要求连续推进到可运行交付

阶段 0：核查与冻结
先确认 Git 状态、AGENTS、三个入口、解释器、当前指纹、可用磁盘和 GPU 占用；不启动完整 Isaac Sim/Isaac Lab 作环境发现。
记录当前官方模型哈希、现有本地修改和最近可用检查点。列出必要适配点后直接开工，别写长方案后停止。
输出机器可读初始 capability 清单和一份简短 ADR，说明为何不合并环境、为何采用工作台编排。

阶段 1：打通最小纵向功能
完成可启动 API、中文界面、真实能力发现、一个真实任务执行、日志流、状态持久化和结果查看。
立刻接入现有三条主链，默认只读展示历史证据，点击运行才新建作业。
先实现关键操作完整闭环，再补美化依赖图。第一版就有项目总览、工作流、作业详情、模型/契约、证据与离线产物入口。

阶段 2：补关键可追溯与等价验证
实现依赖图和真实状态失效、模型注册、基线/候选隔离、负例、行走生产 C++ 输入输出对照。
利用现有 6000 条 MuJoCo 输入和已有导出复验网络数值；注明哪部分是历史/复验/新增。
完成桌面增量编译，再尝试真正的离线 ARM 构建。构建失败先修能修的原因，保留诊断，不因 ARM 单点阻塞界面、比赛、训练和 MuJoCo。

阶段 3：通过工作台端到端验收
下列顺序串行进行，保持预算，不把 GPU 训练与视觉比赛同时跑：
1) 环境只读发现。界面显示各解释器真实版本，Isaac Gym/Sim/Lab 三者不混淆。
2) 桌面编译实际成功，记录现有源码和工具链身份；编译之后实际启动验证。
3) 官方 gait 30 秒；正常视觉比赛 120 秒且录像，读取底层 result 的实际检查项。性能只报本次条件下测值。
4) MuJoCo 行走 120 秒，并核对实际输入对应 TorchScript/比赛 ONNX，至少复用既有 tolerance，额外后端单独报告。
5) Gym 官方回放（4环境×1000步）；若资源紧张先减少有界步数并明确验收覆盖变化。
6) 64环境×3轮 warm-start 验证新训练入口，标明仅 critic 预热；另做兼容的第71轮父检查点 4096环境×1轮 full 恢复验证实际 actor 更新。若当前父检查点发生变化先解析契约，不改成新初始化冒充恢复。
7) 用当前评估器评估一个明确候选并与同条件官方基线比较。若候选不达标，软件的正确行为是显示失败/不足并继续保护官方基线。

十一、必须真实通过的反例与边界检查

- 将 59→13 踢球模型选进行走任务：执行前拒绝，不能自动猜测适配。

- full 恢复缺优化器/RNG、配置不兼容或父指纹不兼容：使用现有规则拒绝，不能回退 warm-start 后仍标 full。
- 外层进程成功但底层质量 FAIL/INSUFFICIENT：前端不得展示质量绿色通过。

- 用户开启浏览器看板但不点运行：不应启动训练、仿真和 DDS。
